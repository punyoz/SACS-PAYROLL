3. Live demo steps

3.1 Self-processed payslip in Branch 3 (Robinson)

  1. Sign in as +acc-b3-1. Payroll → Process Payroll → the current cutoff → Process payroll for all. The Accountant's own row is processed with everyone's, system-computed only.
  2. Submit the run. HR gets a notification "Self-processed payslip to review".
  3. Sign in as +hr1 → Payroll → Payroll Approval: the run shows the flag Self-processed. Approve it.
  4. Back as +acc-b3-1: My Account → My Payslips shows the new payslip (employee share only). The Accountant can never approve it.

3.2 Super Admin fallback (deactivate one HR)

  1. Sign in as +sa1 → Admin & HR Accounts → deactivate Demo HR Two.
  2. Important: the routing counts every active HR account, including the 3 non-demo HR accounts already on production. The fallback appears only when exactly one HR is active, so the other HR accounts must be inactive for this step (open decision 3).
  3. Sign in as +hr1 → My Account → My Leave → file a leave. It goes to the Super Admin: the Super Admin gets a notification, the audit log says "fallback used" and why.
  4. As +sa1: Dashboard → Pending actions shows 1 → open Items Waiting on Fallback → approve (or reject with a reason).
  5. Reactivate Demo HR Two: new items go to HR again and nothing waits on the Super Admin.

3.3 Adding Branch 4's Admin and Accountant

  1. As +sa1: Admin & HR Accounts → add an Admin for Pinugay Branch. As +hr1: User Management → add an Accountant for Pinugay Branch (real inboxes or new plus-address tags).
  2. Sign in as the new Accountant: only Pinugay's people show. Its past payslips (January to October 15) were written by the "Demo seed" actor; the latest cutoffs are waiting to be processed.
  3. Process the waiting cutoff: as the only Accountant there, their own payslip is self-processed. HR approves.

3.4 Two Accountants, one cutoff (Branch 1 or 2)

+acc-b1-1 and +acc-b1-2 open the same cutoff: a payslip already processed is not processed twice, and the run is submitted once (a second submit is refused with a clear message).

4. Login plan

  • One inbox receives every code; the tag in the address (+sa1, +hr2, +acc-b1-1, +emp7 …) says which account it is for.
  • Gmail sends about 500 messages a day from a personal account (2,000 on Google Workspace): 40 accounts are far below it. Avoid repeated sign-ins in a loop; the login code is rate limited.
  • Only one sign-in per account at a time: signing in elsewhere signs the first device out. Use a separate browser profile per role during the defense.
  • Lockout recovery: both Super Admins and both HR have the recovery plan in docs (the other account resets; the Super Admin resets HR).
